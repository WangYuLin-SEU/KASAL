# KASAL Studio 交接说明

基于 `kasalv2` 的 `51a1ec0`，通过独立新分支交付新版桌面界面。旧 Polyscope 入口、算法核心和现有命令保持原样。

## 本次改动

- **新增 Studio**：PySide6 + VTK 浅色桌面界面，左侧模型库、中间三维视图、右侧参数。支持文件/目录拖入、搜索筛选、模型切换和界面偏好记忆。
- **查看与操作**：旋转/平移/缩放、双击聚焦、标准视角、原模型/结果 PLY 切换；支持纹理、点云、PLY 标量、部件显隐、透明度、光照和截图。
- **结果显示优化**：离散分区改用柔和的蓝绿紫配色，已知的烘焙箭头在显示副本中替换为带浅色描边的加粗琥珀色平头轴线，不附加端点标记；轴线统一开关，适应视图包含轴端。
- **分区着色修复**：v1、v2 和 Studio 共用规则，着色时补齐单位变换，确定性地选取参考点，并检查量化后的 RGB 不重复。Studio 根据保存的变换重建旧结果的显示分区；旧 PLY 文件不改写，重新分析后导出的 PLY 才会使用修正着色。BOP 对称变换列表保持原格式。
- **计算与标注**：复用 v1/v2 算法，提供自动分析、已知类型分析、增量批处理、进度和取消；支持不计算直接保存人工标签、自动保存参数草稿、恢复和导出。
- **语言及流程修复**：中英文即时切换，保留当前视图和参数；处理空筛选、后台计算时浏览其他模型、损坏结果提示和外部结果更新等情况。
- **测试收缩**：删除阶段性验证脚本、重复局部检查和大量参数组合，只保留 8 个维护用例；CI 保留 6 项无窗口测试及原有 PyTorch3D 安装检查，并加入新入口的编译检查。

## 数据与兼容边界

- 结果和草稿放在模型库的 `.kasal-studio/`，旧模型旁的标注只读；成功计算后才切换当前结果版本，取消和失败保留原结果。
- 清除结果会移入 `.kasal-studio/.trash`；导出拒绝覆盖同名文件。人工标签单独保存，不沿用旧计算轴系和结果 PLY。
- Studio 依赖单列在 `requirements/studio.txt`，SVG 图标加入包资源，运行数据加入 Git 忽略规则；没有调整既有算法依赖版本。

## 启动和验证

在项目根目录使用已有 `py3d` 环境；只有缺少桌面依赖时才执行安装命令：

```powershell
conda activate py3d
python -m pip install -r requirements/studio.txt
python demo_studio.py
# 指定数据：python -m kasal.studio "D:\models"
```

```powershell
python -m pytest tests -q             # 6 项，CI 使用
python -m pytest tests --desktop -q   # 全部 8 项，需要图形桌面和完整算法环境
```

交接前结果：**8 项通过，0 失败、0 跳过**。用例为 2 项 CLI 流程、1 项 STEP 流程、3 项数据保护检查、2 项桌面流程。v1 CLI 和桌面 v2/纹理计算实际运行；数据集 CLI 测试只替换昂贵的 v2 搜索。现有流程同时检查四重分区、二十面体的 60 个分区及旧结果 180 个分区的颜色唯一性和重复打开的一致性。后续优先维护这些工作流，避免再为已覆盖行为增加独立测试。

## 代码入口与后续维护

| 位置 | 职责 |
| --- | --- |
| `demo_studio.py`、`kasal/studio/__main__.py` | 新版启动入口 |
| `window.py`、`i18n.py`、`theme.py` | 界面组织、即时翻译、样式 |
| `viewport.py`、`geometry.py`、`display.py` | VTK 渲染、标量和显示控制 |
| `model.py` | 模型记录、草稿、结果版本和导出 |
| `controller.py`、`worker.py` | Qt 子进程调度及算法调用 |

表中的模块均位于 `kasal/studio/`。详细功能、操作快捷键和历史修复记录见 [设计文档](studio_design_zh.md)。

当前边界：大模型载入仍在主线程；点云用于查看和人工标注，分析要求三角网格；历史结果不自动清理；未复刻旧渲染器的全部调试面板，也未调整算法分类阈值或精度。维护测试保护主要流程，不代表所有分类和界面细节都已覆盖。
